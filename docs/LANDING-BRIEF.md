# ТЗ на лендинг AI News (rss-ai)

Дата: 22.11.2026. Исполнитель: Codex. Источник правды по деплою — ассистент Hermes (владелец проекта),
Codex делает только файлы лендинга и коммит.

## Задача

Проект `rss-ai` уже опубликован на `https://rss-ai.praktik-ai.ru`, но анонимный посетитель видит
страницу шлюза «Нужен доступ» (401). Нужен статический лендинг, который Caddy отдаёт анонимно,
а приложение остаётся на том же адресе за cookie токена.

Ожидаемый результат: аноним открывает `https://rss-ai.praktik-ai.ru/` и видит страницу проекта;
человек с cookie `demo_sid` видит само приложение.

## Границы работы

Менять можно только каталог `landing/` (новый) и `README.md` (один абзац о лендинге).

Не трогать: `app.py`, `rss_news.py`, `requirements.txt`, `Dockerfile`, `docker-compose.yml`,
`.github/workflows/ci.yml`, `web/`, `static/`, `tests/`, порт 8140. Никаких новых зависимостей —
лендинг статический, только HTML/CSS и один JS-файл.

Не трогать сервер: `/opt/my_projects/rss-ai`, `/opt/demo-gate/projects.json`, `/etc/caddy`.
Выкладку и регистрацию в реестре делает владелец после проверки, не Codex.

Коммит один, в текущую ветку `feature/rss-ai-news`, сообщение `Добавил лендинг AI News`.
Пуш разрешён (PR #3 обновится сам).

## Структура страницы (порядок фиксированный)

1. **Шапка**: текстовый логотип `AI/NEWS` (марка `A` в квадрате акцентного цвета), справа
   ссылка «Портфолио» на `https://praktik-ai.ru` и кнопка «Получить доступ» → `#access`.
2. **Первый экран**: `h1` — «Новости об искусственном интеллекте на русском»;
   подзаголовок: «Лента Wired про ИИ → карточки с переведёнными заголовками. FastAPI и Docker,
   обновление раз в 15 минут.» Две кнопки: «Получить доступ» (`#access`) и «Открыть демо»
   (ссылка на `/` без query — человеку с cookie откроется приложение).
   Справа или под текстом — `hero.v1.webp`: снимок интерфейса приложения.
3. **Что делает проект**: 4 пункта.
   - Забирает RSS-ленту Wired по тегу AI и разбирает позиции: заголовок, дата, описание, ссылка.
   - Переводит заголовки и описания на русский автоматически.
   - Отдаёт страницу с карточками и JSON `/api/news`; ссылка `↗` открывает оригинал на wired.com.
   - Держит ответ в кэше 15 минут, чтобы не дёргать ленту и переводчика на каждый запрос.
4. **Как это работает**: 4 шага.
   - Заявка в Telegram или ссылка от автора — шлюз ставит cookie `demo_sid` на 24 часа.
   - Сервер отдаёт страницу: карточки на русском, дата и порядковый номер.
   - «Обновить» — запрос к `/api/news`; при свежем кэше ответ приходит сразу.
   - Ссылка `↗` ведёт на оригинальную статью.
5. **Пример результата**: два снимка интерфейса с подписями. Подпись описывает то, что видно
   на кадре, без обещаний сверх кадра.
6. **Что внутри демо** — таблица «параметр — значение»:

   | Источник | одна лента Wired, тег AI, до 10 последних публикаций |
   | Перевод | машинный (Microsoft Translator), без редактора |
   | Обновление кэша | 15 минут |
   | Доступ | по ссылке, 24 часа |
   | Чего не делает | своих лент не добавляет, поиска и фильтров нет, истории и базы нет |

7. **Кому подходит**: 3 сценария от лица роли.
   - Читать, что пишут про ИИ, без английского.
   - Посмотреть стенд как пример: FastAPI + Docker + шлюз доступа на одном адресе.
   - Взять за основу своего агрегатора: источник задаётся переменной `RSS_FEED_URL`.
8. **FAQ** — 6 блоков `details/summary`, тексты ниже.
9. **Форма доступа `#access`**: поле «что хотите посмотреть» (необязательное, до 500 символов),
   кнопка «Запросить доступ», подпись «Ссылка приходит в Telegram после подтверждения».
10. **Футер**: `AI/NEWS`, ссылка на портфолио, ссылка в Telegram, страница `privacy/`,
    год, «Перевод машинный и может содержать неточности».

## Тексты FAQ (форма вопроса и ответа, можно править стиль, но не факты)

- **Нужна регистрация?** Нет. Доступ выдаётся ссылкой, ссылка действует 24 часа.
- **Почему перевод иногда корявый?** Он машинный, без редактора. Оригинал открывается рядом по `↗`.
- **Откуда новости?** Одна лента Wired про ИИ; каждая карточка ссылается на wired.com.
- **Можно добавить свою ленту?** В демо нет. В коде источник задаётся переменной `RSS_FEED_URL`.
- **Данные сохраняются?** Нет, базы у приложения нет. Кэш живёт в памяти процесса и пропадает
  при перезапуске контейнера.
- **Сколько стоит?** Демо бесплатное: платных запросов внутри нет, считаются только просмотры страниц.

## Форма доступа: контракт и состояния

Пост идёт cross-origin на хаб, контракт уже работает:

```
OPTIONS https://praktik-ai.ru/api/request   -> 204, CORS для https://rss-ai.praktik-ai.ru
POST    https://praktik-ai.ru/api/request   {"project": "rss-ai", "note": "текст из поля"}
  200 -> {"id": 42, "url": "https://t.me/praktik_ai_portfolio_bot?start=r42"}
  400 -> unknown project   (значит проект не в реестре — сообщить владельцу, не «чинить»)
  429 -> слишком много заявок с этого адреса
```

Состояния: исходное → «Отправляем…» (кнопка disabled) → успех: «Заявка №N принята» и кнопка
«Открыть Telegram». Ошибка не стирает введённый текст. `429` показывается отдельным текстом.
Без JS форма показывает прямую ссылку на `https://t.me/praktik_ai_portfolio_bot`.
Для проверки без сети поддержать `?mock=success|429|error`: параметр читается из `location.search`,
подменяет ответ и помечается в консоли.

## SEO и GEO

- `title` 50–60 символов, ключевая формулировка в начале; `description` 120–155; ровно один `h1`.
- Осмысленного текста ≥ 400 слов; ключ «новости об искусственном интеллекте на русском» в `h1`,
  первом абзаце и одном подзаголовке, без набивки.
- `canonical` на `https://rss-ai.praktik-ai.ru/` без query; `og:title`/`description`/`image`
  (`/og.jpg`, 1200×630)/`url`, `twitter:card=summary_large_image`, `lang="ru"`.
- JSON-LD `SoftwareApplication` (`name`, `applicationCategory: EducationalApplication`,
  `operatingSystem: Web`, `description`, `offers` `price 0` — «демо-доступ по заявке», `url`)
  и `FAQPage`, совпадающий с видимым текстом.
- `llms.txt`: название, одно предложение что это, 4–6 фактов строками (вход, выход, источник,
  перевод, лимит доступа, стек), ссылки на `/` и `https://praktik-ai.ru`.
- Никаких выдуманных чисел: ни частотности запросов, ни «в 10 раз быстрее», ни числа пользователей.

## Производительность и доступность

- Первая загрузка ≤ 300 КБ, LCP < 2,0 с на mobile Slow 4G; hero `fetchpriority="high"`,
  остальные изображения `loading="lazy"`, явные `width`/`height`.
- Локальные woff2, `font-display: swap`, не больше двух гарнитур.
- Контраст ≥ 4,5:1, основной текст ≥ 16 px, видимый `:focus-visible`, `prefers-reduced-motion`.
- Адаптив проверить на 360/390/768/1280/1440: горизонтальной прокрутки нет, таблица на узком
  экране превращается в список «параметр — значение».
- Lighthouse mobile: Performance ≥ 90, Accessibility ≥ 95, SEO = 100.

Снимать с живого локального контейнера, а не рисовать: приложение уже поднято на
`http://127.0.0.1:8140`. Запускать `docker compose up -d` не нужно — контейнер работает.

## Приёмка (прогнать до коммита и показать вывод)

```bash
cd landing && python -m http.server 8010   # открыть / и /privacy/ руками

grep -c '<h1' index.html                                    # ровно 1
python -c "import re,pathlib;h=pathlib.Path('index.html').read_text(encoding='utf-8');\
print('title',len(re.search(r'<title>(.*?)</title>',h,re.S).group(1)));\
print('desc',len(re.search(r'name=\"description\" content=\"(.*?)\"',h,re.S).group(1)));\
print('words',len(re.sub(r'<[^>]+>',' ',h).split()))"      # title 50-60, desc 120-155, words >= 400

python -c "import json,re,pathlib;h=pathlib.Path('index.html').read_text(encoding='utf-8');\
blocks=re.findall(r'<script type=\"application/ld\+json\">(.*?)</script>',h,re.S);\
[print(len(b), json.loads(b)['@type']) for b in blocks]"     # два блока парсятся

python -c "import pathlib,re,posixpath;\
h=pathlib.Path('index.html').read_text(encoding='utf-8');\
refs=[r for r in re.findall(r'(?:src|href)=\"([^\"]+)\"',h) if r.startswith('/')];\
missing=[r for r in refs if not pathlib.Path('.'+r).exists()];\
print('refs',len(refs),'missing',missing)"                    # missing = []
```

Плюс руками: `?mock=success`, `?mock=429`, `?mock=error` в форме; ширина 390 px без прокрутки;
`/privacy/` открывается; все ссылки в футере живые.

Один настоящий POST на `/api/request` после выкладки — не при локальной проверке: он создаёт
реальную заявку и отправляет карточку владельцу.
