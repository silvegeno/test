# Как отправить проект на GitHub

## Первый раз: локальная папка уже создана и в ней есть коммит

`git init` создаёт локальный репозиторий. Имя начальной ветки зависит от настроек Git. У меня сейчас ветка называется `master` — это видно в приглашении Git после коммита и командой `git branch --show-current`. На GitHub обычно используют имя `main`, поэтому перед первой отправкой можно переименовать ветку:

```powershell
git branch --show-current
git branch -M main
git remote add origin https://github.com/silvegeno/test.git
git push -u origin main
```

`origin` — короткое имя удалённого репозитория. Адрес должен вести именно в репозиторий, а не на `https://github.com`. `-u` связывает локальную ветку `main` с `origin/main`; в следующий раз достаточно `git push`.

Проверить результат:

```powershell
git status
git remote -v
```

## Обычная работа после первого push

После изменений в файлах:

```powershell
git add .
git commit -m "Кратко: что изменил"
git push
```

Коммит сохраняет изменения в локальном Git. `git push` отправляет коммиты на GitHub.

## Если проект ещё не скачан на этот компьютер

```powershell
git clone https://github.com/silvegeno/test.git
cd test
```

Чтобы получить изменения, которые уже появились на GitHub:

```powershell
git pull
```

`git pull` обновляет текущую локальную ветку изменениями с удалённого репозитория.

## Термины

- `git init` — начать вести историю проекта локально.
- `git add .` — подготовить изменения к коммиту.
- `git commit -m "..."` — сохранить подготовленные изменения в локальной истории.
- `git remote add origin URL` — указать адрес удалённого репозитория.
- `git push` — отправить коммиты на GitHub.
- `git pull` — получить изменения с GitHub в текущую ветку.
